# Binary Neutron Star Simulations with AthenaK

This tutorial describes how to set up, run, and analyze a binary neutron star (BNS) simulation with `AthenaK` using initial data generated by [`FUKA`](https://bitbucket.org/fukaws/fuka), the Frankfurt University/Kadath initial data framework.

## Prerequisites

- [`AthenaK`](https://github.com/IAS-Astrophysics/athenak) — the simulation code (the `kadath_bns` problem generator is currently under pull request; use the [`pgen/kadath_bns`](https://github.com/alanlam1002/athenak/tree/pgen/kadath_bns) branch on the author's fork)
- [`Kadath/FUKA`](https://bitbucket.org/fukaws/fuka) — spectral initial data library (public release `ET_2025_05`)
- CMake ≥ 3.16, a C++17-capable compiler, MPI, HDF5, FFTW3

---

## Patching Kadath (ET\_2025\_05)

Before compiling Kadath, three source files must be patched to make the
Kadath memory pools **thread-safe** for use inside `AthenaK`'s OpenMP
parallel regions.

### Background

`AthenaK` interpolates FUKA initial data from within an OpenMP parallel
loop.  In the public `ET_2025_05` release of Kadath, the static memory
pools in `MemoryMapper` and `coef_mem` are **process-global** (plain
`static` data members).  When multiple OpenMP threads call into the
spectral coefficient and memory-allocation routines simultaneously, these
shared pools cause data races and incorrect results.

The fix is mechanical: marking each pool `thread_local` gives every
thread its own independent instance of the pool, eliminating all races
without any change to the underlying algorithm.

### Files changed

| File | What changes |
|------|-------------|
| `include/memory.hpp` | `coef_mem::mem_ptrs`, `coef_mem::lengths`, `MemoryMapper::mem_map`, `MemoryMapper::ptr_list`, and (with `KADATH_VECTORMAP`) `MemoryMapper::mem_sizes` — all gain `thread_local` |
| `src/Coef/coef_1d.cpp` | Out-of-class definitions of `coef_mem::mem_ptrs` and `coef_mem::lengths` gain `thread_local` |
| `src/Utilities/memory.cpp` | Out-of-class definitions of `MemoryMapper::mem_map`, `MemoryMapper::ptr_list`, and `MemoryMapper::mem_sizes` gain `thread_local` |

### Applying the patch

A ready-made patch file is provided in [patches/thread_local.patch](patches/thread_local.patch).
Apply it from the root of the Kadath source tree:

~~~bash
cd /path/to/fuka
git apply /path/to/athenak-tutorial-kadath/patches/thread_local.patch
~~~

If `git apply` reports that some hunks are already applied (e.g. on a
version newer than `ET_2025_05`), run

~~~bash
git apply --check /path/to/athenak-tutorial-kadath/patches/thread_local.patch
~~~

to verify the current state before retrying.

### Manual patch instructions

If you prefer to apply the changes by hand, or need to port them to a
different Kadath version, the following three sections list every line
that must be changed.

#### `include/memory.hpp`

Find the `coef_mem` class (around line 55) and add `thread_local` to the
two private static data members:

~~~cpp
// Before
static std::array<std::unique_ptr<double>,2> mem_ptrs;
static std::array<size_t,2> lengths;

// After
static thread_local std::array<std::unique_ptr<double>,2> mem_ptrs;
static thread_local std::array<size_t,2> lengths;
~~~

Inside `MemoryMapper` (around line 92), add `thread_local` to `mem_map`
and `ptr_list`:

~~~cpp
// Before
static mem_map_t mem_map;
static ptr_list_t ptr_list;

// After
static thread_local mem_map_t mem_map;
static thread_local ptr_list_t ptr_list;
~~~

If `KADATH_VECTORMAP` is enabled (around line 84), also patch
`mem_sizes`:

~~~cpp
// Before
static mem_sizes_t mem_sizes;

// After
static thread_local mem_sizes_t mem_sizes;
~~~

#### `src/Coef/coef_1d.cpp`

Find the out-of-class definitions of the `coef_mem` static members
(around line 47) and add `thread_local`:

~~~cpp
// Before
std::array<std::unique_ptr<double>,2> coef_mem::mem_ptrs;
std::array<size_t,2> coef_mem::lengths {};

// After
thread_local std::array<std::unique_ptr<double>,2> coef_mem::mem_ptrs;
thread_local std::array<size_t,2> coef_mem::lengths {};
~~~

#### `src/Utilities/memory.cpp`

Find the out-of-class definitions of the `MemoryMapper` static members
(around line 24) and add `thread_local`:

~~~cpp
// Before
MemoryMapper::mem_map_t MemoryMapper::mem_map;
MemoryMapper::ptr_list_t MemoryMapper::ptr_list;

// After
thread_local MemoryMapper::mem_map_t MemoryMapper::mem_map;
thread_local MemoryMapper::ptr_list_t MemoryMapper::ptr_list;
~~~

If `KADATH_VECTORMAP` is enabled, also patch the `mem_sizes` definition:

~~~cpp
// Before
MemoryMapper::mem_sizes_t MemoryMapper::mem_sizes;

// After
thread_local MemoryMapper::mem_sizes_t MemoryMapper::mem_sizes;
~~~

Additionally, make sure the file ends with a newline after the closing
brace of the `Kadath` namespace.

## Compilation

Compilation proceeds in two stages: first build the Kadath library, then
build `AthenaK` against it.

### Step 1 — Build Kadath/FUKA

After applying the patch above, build Kadath from its source tree.
Kadath is built separately and produces a static library
`lib/libkadath.a` that `AthenaK` links against.

For detailed installation instructions, including platform-specific
dependency setup and CMake configuration, refer to the
[official FUKA documentation](https://samueltootle.github.io/fuka/index.html).

On success the library is written to `/path/to/fuka/lib/libkadath.a`.

### Step 2 — Link Kadath into the AthenaK source tree

`AthenaK`'s build system expects to find Kadath at
`${ATHENAK_ROOT}/kadath`.  Create a symbolic link from the AthenaK
root to the Kadath source tree:

~~~bash
cd /path/to/athenak
ln -s /path/to/fuka kadath
~~~

The CMake configuration will then find `kadath/include/` for headers
and `kadath/lib/libkadath.a` for the pre-built library.

### Step 3 — Build AthenaK

Before configuring, ensure the following libraries are available in
your environment:

- **MPI** — for distributed-memory parallelism
- **FFTW3** — used by Kadath for spectral transforms
- **LAPACK/BLAS** — used by Kadath for linear algebra (e.g. MKL, OpenBLAS)
- **GSL** — GNU Scientific Library
- **Boost** — header-only components used by Kadath

With these in place, create a build directory and run CMake with
`-DPROBLEM=kadath_bns`, which selects the
[`kadath_bns`](https://github.com/alanlam1002/athenak/blob/pgen/kadath_bns/src/pgen/kadath_bns.cpp)
problem generator and activates the Kadath dependency block in
`CMakeLists.txt`:

~~~bash
cd /path/to/athenak
mkdir build && cd build
cmake -DPROBLEM=kadath_bns \
      -DAthena_ENABLE_MPI=ON \
      -DAthena_ENABLE_OPENMP=ON \
      ..
make -j8
~~~

Additional Kokkos and compiler flags may be needed depending on your
platform and target architecture; refer to the `AthenaK`
[wiki](https://github.com/IAS-Astrophysics/athenak/wiki/Build) for
further guidance.

## Initial Data Generation

BNS initial data are generated using FUKA's `bns_xcts` solver, which
produces a checkpoint file (`.dat`) containing the spectral
representation of the initial solution.  For a full walkthrough of the
solver setup, parameter configuration, and execution, refer to the
[official FUKA documentation](https://samueltootle.github.io/fuka/index.html).

## Running the Simulation

### Input parameter file

A template input file is provided at
[`inputs/dyngr/kadath_bns.athinput`](https://github.com/alanlam1002/athenak/blob/pgen/kadath_bns/inputs/dyngr/kadath_bns.athinput)
in the `AthenaK` source tree.  Copy and edit this file before running.

### FUKA-specific parameters

Three parameters in the input file are specific to the FUKA initial data:

**`initial_data_file`** (in `<problem>`) — path to the Kadath `.info`
configuration file produced by the FUKA solver.  FUKA initial data
always comes as a pair: `bns_solution.info` and `bns_solution.dat`.
The `.info` file is what `initial_data_file` points to; the `.dat`
file must share the same base name and reside in the same directory.

~~~text
<problem>
initial_data_file = /path/to/bns_solution.info
~~~

**`table`** (in `<problem>` and `<mhd>`) — required only when using a
tabulated equation of state.  Table files use the `AthenaK` tabulated
format (`.athtab`) and can be generated from
[CompOSE](https://compose.obspm.fr/) data using
[PyCompOSE](https://github.com/computationalrelativity/PyCompOSE).

- `<problem>` expects a **1D beta-equilibrium table**, used to
  reconstruct the thermodynamic state of the cold, equilibrated matter
  in the FUKA initial data.
- `<mhd>` expects the **full tabulated EOS**, used during the dynamical
  evolution.

~~~text
<problem>
table = /path/to/eos_beta_eq_1d.athtab

<mhd>
dyn_eos = table
table   = /path/to/eos_table.athtab
~~~

For a piecewise-polytrope EOS (as in the template), the `table` entries
are not needed and the EOS parameters are set directly in `<mhd>`.

### Setting `HOME_KADATH`

Before launching `AthenaK`, export the `HOME_KADATH` environment
variable pointing to the Kadath directory linked inside `AthenaK`:

~~~bash
export HOME_KADATH=${HOME}/athenak/kadath
~~~

This must be set in the shell or in the batch submission script before
invoking the executable.  The `kadath_bns` problem generator uses it to
locate the EOS data files under `$HOME_KADATH/eos/`, which are needed
to reconstruct the equation of state used when building the FUKA
initial data.

### Launching the code

~~~bash
mpirun -np <N> ./build/src/athena -i kadath_bns.athinput
~~~
